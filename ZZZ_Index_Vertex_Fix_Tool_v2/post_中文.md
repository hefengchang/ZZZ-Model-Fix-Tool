# 绝区零 索引与顶点修复工具 v2

一个独立运行的绝区零 mod 修复工具，专治游戏更新后坏掉的两类问题：

- **腿弯 / 塌陷 / 扭曲，贴图正常** —— `blend.buf` 里的骨骼索引错了
- **贴图整体错乱，模型形状正常** —— `texcoord.buf` 的顶点格式跟游戏对不上了

外加一键**通用脸部修复**，专修 3.1 → 3.2 更新里坏掉的那批脸。

界面中英文可切，窗口里输 `lang` 随时换。改动前一律自动备份，选一个键就能还原。

**包里预置了一批常用网格的参照数据**，覆盖到的角色开箱就能修。没覆盖到的，用 **gui_collect** 花几分钟自己抓一份 —— 作者不再更新预置数据。通用脸部修复完全不需要参照。

---

## 用之前先确认

1. **XXMI / 3DMigoto 装好，mod 能在游戏里加载。** 如果 mod 在游戏里压根不显示，这工具帮不上忙，那是另一个问题。
2. **mod 的 hash 是当前版本的值。** 老版本做的 mod，先用你手上的 hash 更新工具把 hash 更新到当前版本（各人叫法不同，效果一样）。本工具靠 hash 认网格，hash 是旧的 → 什么都匹配不上 → 什么都不修。
3. **一次只拖一个 mod。** 拖**那一个 mod 自己的** `ini` 和 `Buffer` 所在文件夹，别拖整个 `Mods` 目录，否则会把别人的 mod 一起扫进来。
4. **同一个 mod 不要跑第二遍。** 已经修过的文件会自动识别并跳过，但别去试运气。
5. **骨骼索引和顶点格式这两类修复，需要该网格的参照。** 包里预置了常用的那批；没有的用 gui_collect 自己抓（见下文）。通用脸部修复（模式 2）不需要参照。

---

## 怎么用

1. 解压到任意位置。`Dump` 文件夹要跟脚本放在一起 —— 预置的参照在里面，你自己抓的也放这里。
2. 双击工具。
3. 选语言：`1` = 中文，`2` = English。
4. 选模式：
   - `1` = **索引与顶点修复** —— 日常用的就是这个，骨骼索引和顶点格式一起查一起修。
   - `2` = **通用脸部修复** —— 只修 3.1 → 3.2 坏掉的脸。
   - `3` = 查看通用脸部修复覆盖了哪些角色。
5. 模式 1 还要选一组参照（`Dump` 里的一个文件夹）。启动时列出来的就是现有的全部，每组管什么写得很清楚，比如 `Dialyn-Face — Face`。
6. 把 mod 文件夹拖进窗口，按 Enter。
7. 选 `1` = 修复，`2` = 还原，`c` = 换一组参照，回车 = 跳过，`q` = 退出。
8. 看清工具列出的改动计划，确认没问题就输入 `start` 回车。

就这么简单，进游戏看效果。

`Dump` 是空的时候，工具启动就会把抓取步骤和两个链接打出来，不用你记。

窗口开着时还能输：

| 输入 | 作用 |
| --- | --- |
| `lang` | 切换 中文 / English |
| `m` | 换模式 |
| `c` | 换一组参照 |
| `3` | 查看通用脸部修复覆盖哪些角色 |
| `q` | 退出 |

命令行调用：`python ZZZ_Index_Vertex_Fix_Tool.py [-zh|-en] [universal] [restore] <mod 文件夹>`

## 用 gui_collect 抓参照 dump

`Dump` 里没有的网格才需要抓。一个网格抓一次，第一次大概几分钟。

1. 装 **[gui_collect](https://github.com/Petrascyll/gui_collect)** —— 要 Python 3.9+，`texconv.exe` / `texdiag.exe` 在它的 `modules` 目录里。双击 `launch.bat` 启动。
2. 打开 **XXMI 启动器**，进齿轮设置，找到对应游戏的 **MI 页**，勾上 **Enable Hunting**。**必须在启动游戏之前勾。**
3. **关掉 mod 再进游戏** —— 按 `F6`，或者更保险的做法：把 `Mods` 文件夹改名、加 `DISABLED` 前缀（着色器类 mod 可能不会被 F6 关掉）。
4. 走到你要抓的角色出现在画面里。按**小键盘 0** 进狩猎模式（屏幕上下会出现绿色文字）。`F12` 看按键说明，`Ctrl + F12` 是狩猎相关的。
5. 找到目标网格，复制它的 **IB hash**（标记 hash 就会复制到剪贴板）。
6. 抓一次 **Frame Analysis**，然后打开 gui_collect，选中那个 Frame Analysis 文件夹、粘贴 IB hash、给对象起个名字（只能是字母数字，不能有空格），导出。

导出来就是一个文件夹：`hash.json` 加几个文本 dump。把它丢进 `Dump\` —— 一个网格一个文件夹，命名成 `角色-部位`：

```
Dump\
    Dialyn-Face\
        hash.json
        DialynFaceA-vb0=c44d2531.txt
        DialynFaceA-ib=facb2461.txt
```

完整图文流程：**[3DMigoto 狩猎与导出教程](https://leotorrez.github.io/modding/guides/hunting)**

这个文件夹的两条规矩：

- **一个网格一个文件夹，别按角色合并。** 一个文件夹 = 一组参照 = 一次修复的范围。合并了会把已经修过的网格重新带上，同一个网格修第二遍。
- 名字只影响显示，随便改 —— 工具读的是 `hash.json` 里的内容，不认文件名。

也可以直接把 dump 文件夹拖进工具窗口，当次就能用，不用拷进 `Dump\`。

## 原理（简述）

**骨骼索引。** `blend.buf` 里每个顶点带 4 个骨骼索引。游戏更新会重排骨骼数组，mod 里烘焙的旧编号就指到了错的骨头上。工具按位置把 mod 的顶点和游戏的顶点配对（空间网格，半径 0.01 游戏单位），对每一对位置对得上、而且某个槽位权重也一致的顶点投一票 `mod 索引 → 游戏索引`，再把票数整理成一一对应的映射写回 buf。权重是第二重判据：位置相同 **且** 权重相同，基本就是同一根骨头。

**顶点格式。** 游戏把顶点 COLOR 从 4 字节改成 4 个 float，texcoord 布局从每顶点 36 字节变成 48 字节 —— mod 的 buf 和 ini 里的 `stride` 对不上了，贴图按错的偏移去读，就糊了。工具逐顶点重排并改掉 stride。只有在 buf 大小、顶点数（从 blend 缓冲按 hash 找，不依赖命名）、dump 里读到的实时布局三者对得上时才动手，对不上就打印提示跳过。

**hash。** ini 里的 `hash =` 就是游戏那边的缓冲 hash。只有 mod 属于你选的参照组，工具才处理它 —— 靠这些 hash 认。所以 hash 是旧版的，就什么都匹配不上。

完整原理 —— 容差、阈值、已知局限 —— 见包里的 `原理说明.md`。

## 我这是哪种问题？

| 游戏里的现象 | 是什么 | 用哪个修 |
| --- | --- | --- |
| 腿向后折、身体塌陷、手臂扭曲 —— 贴图正常 | 骨骼索引 | 模式 1（VGX） |
| 贴图糊成一团、错位铺满整个模型 —— 形状完美 | 顶点格式 | 模式 1（texcoord） |
| 3.1 → 3.2 更新后**只有脸**坏了 | COLOR 块布局变了 | 模式 2，或模式 1 |
| 模型完全不显示 / mod 根本没加载 | 不归这工具管 | 检查 XXMI 配置和 mod 的 hash |

模式 1 会把两类问题一起查、一起列、一起修。没匹配上的网格，工具不碰。

## 安全

- 改之前一律备份：buf 是 `*.texfmt_BACKUP.buf`、`*.vgx_BACKUP.buf`，ini 是 `*.texfmt.bak`。
- 在窗口里选 `2` = 还原，就能把这工具在那个文件夹里改过的东西全部退回。
- 不属于本次所选参照的 mod，工具拒绝碰。ini 里一个参照 hash 都没有，整包原样不动 —— 防止把角色修串。
- 它不猜数据。算不出顶点数、判断不出格式，就打印一行提示然后跳过该文件。

## 常见问题

**工具说「没有命中的网格，或都已经修过了」。**
要么这个网格本来就不需要修，要么 mod 的 hash 是旧的（先把 hash 更新到当前版本），要么参照组选错了 —— 输 `c` 换成对应的那组。

**我的角色不在预置参照里。**
用 gui_collect 抓一份，见上文那节。`Dump` 为空时工具启动就会打出同样的步骤和链接。除了通用脸部修复，没有参照就没法修 —— 没有东西可以拿来跟 mod 比对。

**能一次修好几个 mod 吗？**
在同一个窗口里一个接一个拖进来就行。别拖一堆 mod 的父目录。

**抓好的 dump 文件夹能分享给别人吗？**
能，格式通用，换个人一样用。

**能用在别的游戏上吗？**
不能。参照格式和 hash 名单都是绝区零专用的。

**修坏了怎么办？**
对同一个文件夹选 `2` = 还原，全部退回原始文件。
