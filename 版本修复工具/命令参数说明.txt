绝区零 Mod 修复工具（中文版）命令参数说明
适用：zzz_fix.中文版.py / zzz_fix.中文版.exe
     独立版\版本Hash修复独立版.exe（独立单文件版，见第八节）
================================================


一、两种启动方式
------------------------------------------------
不带任何开关启动 = 图形界面。双击 exe，或者直接运行 .py，都是这个。
带 --cli 启动 = 以前的黑色窗口（命令行）模式，只做版本 Hash 修复。

exe 是按「无控制台」的窗口方式打包的，所以 --cli 启动时会自己开一个黑窗；
如果本来就是在 cmd 里敲的命令，就直接复用那个 cmd 窗口，不另开新窗口。


二、命令行参数
------------------------------------------------
--cli / -c / --console
    切到命令行（黑色窗口）模式。三个写法完全等价，写一个就够。

    没给路径时：先做一次启动更新检查（只有在配置了更新仓库时才会查），
    然后进入拖放循环，停在窗口里等你拖文件，不会自己退出。

paths（位置参数，可以写多个）
    要修的 .ini 文件或文件夹。给文件夹会递归处理里面所有 .ini。

    · 可以只写路径、不带 --cli，那样走图形界面，路径会预填进「手动路径」；
    · 支持一次给多个，用空格隔开；
    · 路径含空格又没加引号时，程序会自己尝试把被拆开的参数拼回去；
    · 也接受 file:/// 开头的路径（会自动去掉前缀）；
    · 不是 .ini 的文件跳过；
    · 文件名以 DISABLED 开头的 .ini 跳过（当作已禁用），DESKTOP 开头的也跳过；
    · 文件夹扫描只认小写 .ini 结尾（.INI 不会被扫到）；
    · 路径不存在时打印「路径不存在」并跳过，不影响后面的路径。

    给了路径就不会做启动更新检查，直接开始修。

-h / --help
    显示帮助后退出。带 --cli 时写它，帮助会打印在黑窗里：
        zzz_fix.中文版.exe --cli --help
    不带 --cli 时写 -h 只会打开图形界面，帮助内容不显示。


三、用法示例
------------------------------------------------
zzz_fix.中文版.exe
    图形界面（默认）。

zzz_fix.中文版.exe --cli
    黑窗模式，开好窗口等你拖放。

zzz_fix.中文版.exe --cli "D:\ZZMI\Mods\某个mod"
    黑窗模式，先把指定文件夹修一遍，再停在拖放循环里接着等。

zzz_fix.中文版.exe "D:\ZZMI\Mods\某个mod"
    图形界面，路径预填到「手动路径」。

python zzz_fix.中文版.py --cli D:\mods
    源码方式跑，行为一样。

想双击就进黑窗：给 exe 建个快捷方式，在「目标」末尾加一个空格再加 --cli。
以后把 mod 文件夹拖到那个快捷方式上，也走黑窗模式。
（直接拖到 exe 本体上是图形界面。）


四、黑窗模式里可输入的命令
------------------------------------------------
窗口提示「拖放文件/文件夹 (或输入 exit 退出):」时：

拖入文件/文件夹，或直接输入路径，回车
    执行修复。可以一行贴多个路径（一次拖多个文件到控制台就是这种格式），
    含空格的路径用引号包起来。

update / up / 更新 / 检查更新
    手动检查更新（会问你要不要下载）。独立版没有这条，见第八节。

exit / quit / q / 退出
    退出程序。

空行回车
    忽略，继续等下一次输入。

修复完成后不会自动退出，会回到这个提示符，可以接着拖下一个。
另外，黑窗模式下这个工具自带颜色（ANSI），不支持颜色的老控制台只是没颜色，
不影响功能。


五、图形界面下的拖放
------------------------------------------------
把 .ini 文件或文件夹拖到 exe 上（不带 --cli）：走图形界面，拖入的内容进「手动路径」。
也可以直接把文件拖进已经打开的窗口里。


六、设置文件 zzz_fix_设置.json
------------------------------------------------
和 exe / .py 放在同一个目录，程序自己读写，一般不用手改（界面里改了会自动写回）。
手工编辑时可用字段：

use_default          true / false      启动时自动使用下面的默认修复文件夹
default_folder       "E:\\ZZMI\\Mods"  默认修复文件夹
theme                "dark" / "light"  界面主题；不填按时间自动选（7:00~19:00 日间）
update_auto_start    true / false      启动时自动检查更新
update_gitee_repo    覆盖代码里的 Gitee 仓库（"用户名/仓库名"，测试用）
update_github_repo   覆盖代码里的 GitHub 仓库
iv_dump_dirs         ["..."]           索引与顶点修复用的 dump 参考目录
update_ignored       点过「忽略此版本」的版本号


七、说明
------------------------------------------------
· --cli 只影响「版本 Hash 修复」。索引与顶点修复在本程序里只有图形界面入口，
  没有命令行开关。

· 独立的「索引与顶点修复工具\索引与顶点修复工具.py」另有自己的参数：
      python 索引与顶点修复工具.py [apply] [universal] [restore] <mod文件夹>
  不写就是修复（apply），restore 是还原；universal 是通用脸部修复模式，
  也可以写成 univ / tongyong / 通用 / -u。
  细节看那个文件夹里的 使用说明.txt。

· 两种模式共用同一个设置文件和同一套自动更新。
  自动更新重启后会回到原来的模式：黑窗模式更新完还是黑窗，不会被弹回图形界面。


八、独立单文件版：独立版\版本Hash修复独立版.exe
------------------------------------------------
发布 zip 里除了主程序，还有一个独立版，放在 独立版\ 文件夹里：

· 约 12 MB，单个文件，不依赖任何其他文件。把整个"独立版"文件夹拷到 U 盘、
  桌面、任意地方都能直接跑，不用带"依赖包勿删"、不用带 dump、不用带任何东西。
· 双击就是黑窗，直接进拖放循环。它不会开图形界面，也不需要写 --cli。
· 只做版本 Hash 修复，没有图形界面，也没有索引与顶点修复。
· 完全不带更新功能：启动不查，窗口里输 update 也只会提示你去重下主 zip。
  它只跟主 zip 一起发布 —— 想要新版就重新下载主压缩包，解压后把 独立版\
  里那个 exe 覆盖过来即可（旁边那些 依赖包勿删 之类不用管）。

用法：
    双击 独立版\版本Hash修复独立版.exe                开黑窗，拖 mod 文件夹进去
    版本Hash修复独立版.exe "D:\ZZMI\Mods\某个mod"    先修指定文件夹，再进拖放循环
    版本Hash修复独立版.exe --help                    看帮助

第四节的拖放命令，除了 update 之外都认（拖路径、exit 那些）。它的设置文件是
独立版\zzz_fix_设置.json —— 一般不存在，没有就用默认值，不影响修复。

它靠打包时塞进 exe 内部的构建标记认出自己是独立版，所以随便改名、挪到任何
目录、拷到 U 盘，都还是黑窗。只有在标记丢了的情况下（用旧包、或者手工重打包
时漏了 --add-data）才会退回按文件名判断，那时候名字不对就会开成图形界面 ——
按文件名认的名字在代码顶部的 STANDALONE_NAMES 里。

本说明（命令参数说明.txt）随主 zip 一起发，解压后就在程序目录里。
