索引与顶点修复工具 —— 使用说明
================================================

名字里的两样东西
    索引 = blend.buf 里的骨骼索引（VGX）
    顶点 = texcoord.buf 里的顶点格式

作用
    一次拖一个 mod 文件夹进去，两类问题一起查、一起列、一次确认、一起修：

        一、骨骼索引（VGX）
            症状：模型变形 —— 腿弯、塌陷、扭曲，但贴图正常
            原因：blend.buf 里的骨骼索引被写错了
            做法：按角色表把索引逐个换成正确的

        二、顶点格式（texcoord）
            症状：贴图整体错乱，但模型形状完全正常
            原因：游戏更新改了顶点格式，老 mod 的 buf 布局对不上
            做法：按目标表重排每个顶点的字节，并同步改 ini 里的 stride

    两类互相独立，哪个命中修哪个；都没命中就什么都不做。


两套模式
------------------------------------------------
    启动时先选这次用哪套（拖放界面输 m 可以换）：

        1 = 索引与顶点修复（默认）
            就是上面那两样：VGX 按角色表，texcoord 按 TEXCOORD_TARGETS
            表或 dump 参照。要选一组参照。

        2 = 通用脸部修复
            3.1 -> 3.2 更新里 texcoord 变过的那批网格，只有一种变化，
            写死在代码里，不用填格式，也不需要参照：

                texcoord 里最前面那块顶点 COLOR
                4 字节（R8G8B8A8_UNORM）-> 4 个 float
                每顶点多 12 字节（旧 36 -> 新 48 字节/顶点）

            认 UNIVERSAL_HASHES 那张名单：53 个网格 / 46 个角色。
            启动那一步选 3（或在拖放界面输 3）可以看到完整名单。
            这个模式只动 texcoord buf 和 ini 里那行 stride，
            骨骼索引（VGX）不碰。

        （原来独立的 通用脸部修复.py 已经并进本工具，那个脚本删了。
          备份后缀两边一样，还原是同一套。）

    命令行：

        python 索引与顶点修复工具.py [universal] [restore] <mod文件夹>

        universal   直接进通用脸部修复模式（不写就是索引与顶点修复）

    「通用脸部修复」模式认到 hash 之后还要过这几道（全部按文件自己算）：

        1. 那个资源节有 filename = xxx.buf 和 stride = N
        2. 顶点数从同目录的 Blend.buf ÷ 32 反推，有 Position.buf 就 ÷ 40 再对一遍
        3. 每顶点字节数 = buf 大小 ÷ 顶点数，得能整除
        4. 每顶点字节数正好是 36 -> 转；已经是 48 -> 跳过了，别的数 -> 不动

    任何一条不满足就跳过不动，理由会打出来。ini 里 hash 还是旧的那种会提醒
    「先跑版本修复工具」，并显示 旧 -> 新 是哪个值。


用法
------------------------------------------------
    双击 索引与顶点修复工具.py（或命令行 python 索引与顶点修复工具.py）

    第零步：选这次用哪套（索引与顶点修复 / 通用脸部修复，回车 = 索引与顶点修复）
            选完会把那套的说明打一遍（这个模式干什么、能修哪些、怎么拖），
            后面输 m 换模式也会再打一遍。

    第一步：选这次修哪个角色（通用模式跳过这步，它不看参照）

        dump\ 里有这些角色的参照数据：
          1. 珂蕾妲        珂蕾妲-脸
          2. 琉音         琉音-脸、琉音-身体
          3. 艾莲         艾莲-身体
          4. 薇薇安        薇薇安-脸
          5. 露西         露西-脸

          这次修哪个角色？输序号（回车 = 1）: 2

        选完只拿这个角色的 dump 当参照，不会跨角色匹配。
        dump\ 里只有一个角色时不问，直接用那个。
        想换：在拖放界面输 c。
        （没有"全都用"这个选项 —— 跨组匹配会把别的组的网格也扫进来。）

    第二步：把【那个角色的 mod 文件夹】拖进来，按 Enter，然后选：

        1 = 修复      先列出两类问题，输入 queren 才动手
        2 = 还原      把本工具改过的文件按备份退回去
        回车 = 跳过   这个文件夹不动
        q = 退出

    也可以直接把 mod 文件夹拖到 .py 文件图标上，一步到位
    （这种走法不提问，dump\ 里的全都用，模式是索引与顶点修复）。
    命令行：python 索引与顶点修复工具.py [universal] [restore] <mod文件夹>

    拖放界面能输的指令：
        c = 换参照组（重选参照）      仅索引与顶点修复模式
        m = 换模式（两套之间切）
            —— 切回索引与顶点修复时会重新问一次参照组（通用模式那边用的是
               全部 dump，不重选就会跨组匹配）
        3 / l = 看通用脸部修复能修哪些角色
        q = 退出


警告
------------------------------------------------
    一次只拖一个角色 mod 的文件夹（它自己的 ini 和 Buffer）。
    不要把整个 Mods 目录拖进来 —— 工具是递归扫整个文件夹找 ini / buf 的，
    拖根目录会把所有角色的 mod 全扫一遍，VGX 那部分撞上同 hash 就可能改错。


dump 驱动（普通用户不用管这一节）
------------------------------------------------
    dump 里有这个网格当前的所有信息，比手填表准：

        CategoryHash.Texcoord -> 该填什么 hash
        CategoryHash.Blend    -> 反推顶点数用
        元素表                 -> 当前是什么格式

    【普通用户】什么都不用做。dump\ 里的文件是作者放好的，程序启动自动读：

        dump 已读：3 个网格，角色：琉音、艾莲、露西

    里面缺哪个角色/网格，反馈给作者补一份就行。

    【作者】把 F8 抓的 Frame Analysis dump 的 json 丢进 dump\，改成角色名：

        索引与顶点修复工具\
            dump\
                琉音.json
                艾莲-脸部.json
            索引与顶点修复工具.py

        角色多的话，也可以一个角色一个子文件夹：

            dump\
                琉音\
                    a1b2c3d4-12345-0.json
                艾莲\
                    ...

        json 内容不依赖文件名，随便改。整个 3DMigoto 那种嵌套目录
        （<ib hash>-<n>-<i>\TYPE_...\xxx.json）直接拷进来也行，会递归找。

        程序不自动建这个文件夹（建错地方会让人以为数据没放），
        位置放对就行，启动时扫这两个地方，两处都有时后者优先：
            程序目录\dump\          （exe 旁边；脚本跑时 = 脚本旁边）
            程序目录的上一级\dump\  （脚本放在 py代码\ 这类子目录里时用这个）
        一个都没有就提示一句，其余功能照常 —— 只是靠 dump 推的网格认不出来。

        也可以拖别的 dump 文件夹进窗口临时读（有 .json、没有 .ini 会被认出来），
        或者脚本顶部填绝对路径：DUMP_DIRS = [r'D:\dump', ...]

    表和 dump 都有同一个网格时，会问一次用哪个：

        表里和 dump 里都有这个网格：dafc9647
          1 = 用表里的
          2 = 用 dump 里的
          选 1 / 2（直接回车 = 表）:

        默认值由脚本顶部 PREFER_DUMP 决定（False = 表，True = dump）。
        非交互运行（比如被别的程序调用）时不会问，直接用 PREFER_DUMP。

    旧格式怎么来的：dump 只给了新格式，工具自己倒推 —— 把新格式里某个
    float4 块缩成 4 字节（或 half4），看哪个的每顶点字节数正好等于 buf 的实际值，
    倒推结果会打印出来给人核对。

    注意
        - 前提还是那个：mod 的 ini 里 hash 必须已经是当前值（先跑版本修复工具），
          否则按 hash 找不到节
        - 表格不是没用了：可以把 dump 的结果固化进表格，不依赖 dump 也能修，
          也方便分享给别人

    骨骼索引（VGX）也能自动推
        同一个网格文件夹里再放上它的 -*Blend.buf 和 -*Position.buf，
        工具就能拿 dump 当参照自己推索引映射：

            拖 mod 进来 → 用 dump 的 CategoryHash 去 ini 里定位到那个 buf
                        → dump 和 mod 逐顶点按位置配对（权重也要对得上）
                        → 投票得出 旧索引 -> 新索引

        原理：mod 的网格通常是游戏原网格的细分 / 平滑版，位置对得上。
        实测琉音身体：mod 351810 顶点 / 游戏 15715 顶点，位置最近距离中位
        0.0033（身高的约 0.3%），推出来的映射和已知的表比对 25/26 一致。

        要哪三个文件：

            json            该网格的 CategoryHash（定位 mod 那边是哪个 buf）
            -*Blend.buf     新编号的骨骼索引（投票的目标）
            -*Position.buf  位置（配对用，缺了这个就推不了）

        抓 dump 时这三样本来就在同一个 TYPE_ 目录里，整个文件夹拷过来即可。
        只有 json（缺 Blend/Position）的网格，VGX 那块就只能走表。

        用哪个来源：

            表里和 dump 里都能修同一个网格 -> 问一次：
                1 = 用表里的（推荐，人手填过）
                2 = 用 dump 自动推的
            表里没有、只有 dump 能推     -> 问一次要不要修

        推出来的映射会连票数一起列出来，票数少于 20 的标黄提示重点核对。

        另一条路（不需要 mod，也不需要 dump）：拿【旧版本 dump 的 Blend.buf】
        和【新版本 dump 的 Blend.buf】喂 查找VGX映射工具。同一个游戏网格的
        两个版本顶点数一致，配得干干净净。局限：得在更新前存好旧 dump。


脚本里三张表（加新角色 / 新网格看这里）
------------------------------------------------

    ① VGX_CHARACTERS —— 骨骼索引映射

        {
            'name':   '琉音 Dialyn 身体',
            'hashes': ['ff36809b'],        # 该角色 Position 节的 hash
            'old':    [18, 19, 20, ...],   # 现在写错的索引
            'new':    [20, 18, 19, ...],   # 应该是什么
        },

        hash 从哪来：打开 mod 的 ini，找带 vb2 = ResourcexxxBlend 的那节，
                    看它的 hash = 是多少。
        old/new 从哪来：用 查找VGX映射工具（拿"损坏 buf"和"正确 buf"对比）生成。

    ② TEXCOORD_TARGETS —— 顶点格式重排

        {
            'name':       '琉音 Dialyn 脸部',
            'hash':       'dafc9647',                      # 当前版本的 texcoord hash
            'old_format': ('4B', '2f', '2f', '2f', '2f'),  # 36 字节
            'new_format': ('4f', '2f', '2f', '2f', '2f'),  # 48 字节
            'blend_hash': '08923d3e',                      # 选填，见下
        },

        hash 从哪来：游戏内 dump 那个网格的 json，看 CategoryHash.Texcoord。
        old/new_format 从哪来：用 查找Texcoord映射工具 生成（它会连 hash 一起给）。

        记法：'4B'=4 字节  '2e'=2 个 half  '2f'=2 个 float  '4f'=4 个 float
              '4I'=4 个 uint32  '3f'=3 个 float

        blend_hash（选填）← dump 的 CategoryHash.Blend，该网格【blend 节】的 hash。
            修之前要先确认 buf 到底是不是旧格式，判断顺序：
                1) 按 buf 大小：只能被旧步幅整除 = 旧格式，只能被新步幅整除 = 已修过
                2) 大小有歧义时反推顶点数（144x36 = 108x48 = 5184 这类）：
                   先按 blend_hash 找 blend 缓冲（不依赖命名），没填就按同名文件推
                3) 都判不出来 -> 只提示，不动文件

    ③ UNIVERSAL_HASHES —— 通用脸部修复的名单（模式 2 用这张）

        '新 texcoord hash': ('旧 texcoord hash', '是哪个网格'),

        hash 从哪来：Hash变动日志.txt 里那行 "texcoord_vb: 旧 -> 新"，
                    冒号后面那个（"更新后"）就是新 hash，前一个填进括号。
        格式不用填：这个模式固定就是顶点 COLOR 4 字节 -> 4 个 float、
                    每顶点 36 -> 48。别的形状（20 -> 32 那些）走 ② 那张表。
        程序只认这张表：一个 ini 的节 hash 命中表里某条，就跟它 vb1 绑的
        buf 走；命中不了不动。加新角色就往这张表里加一行。

    改完表之后，拖着跑一次，工具会先打印命中情况再问确认，不会直接改文件。


备份与还原
------------------------------------------------
    VGX 部分：    xxx.vgx_BACKUP.buf        原 buf
                  xxx.vgx_REMAP_APPLIED.empty  已修标记

    格式部分：    xxx.texfmt_BACKUP.buf     原 buf
                  xxx.texfmt.bak            ini 原文件
                  xxx.texfmt_DONE.empty     已修标记
                  （旧版工具留下的 .tex48_BACKUP.buf / .tex48.bak 还原时也认）

    通用脸部修复模式写的备份和「格式部分」是同一套（原来那个独立脚本也是），
    还原不区分模式，选 2 一起还原。备份和标记还完就删掉，文件夹回到没修过的样子。

    还原：窗口里选 2，或 python 索引与顶点修复工具.py restore <mod文件夹>
    只认本工具的备份；旧工具那种改名式备份（DISABLED_BACKUP_*）要手动改名回来。


注意事项
    - 一个 buf 不要跑两次（有备份/标记的会自动跳过）
    - 修坏了：选 2 还原
    - 会顺手提醒"看着是旧格式、但没被处理"的 texcoord（工具不会动它们），
      并说明原因：① mod 的 ini 里 hash 还是旧的 -> 先跑版本修复工具
                  ② 这个网格还没 dump -> 抓一份放进 dump\
    - 版本更新后：先跑【版本修复工具】把 hash 更新到最新，再跑本工具
    - 通用脸部修复模式（模式 2）只动 texcoord buf 和 ini 里那行 stride，
      骨骼索引（VGX）不碰；也不看 dump 参照，所以不用选角色。
      它提醒"看着还是旧格式、但没认到名单里的 hash"时，原因只有两种：
          ① 这个网格不在这批通用修复里（或者它的 hash 又变了，表没跟上）
          ② mod 的 ini 里 hash 还是旧的 -> 先跑版本修复工具
